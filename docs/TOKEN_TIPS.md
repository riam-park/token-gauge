# 토큰과 캐시, 초보자를 위한 정리

Claude Code를 쓰다 보면 "왜 한도가 이렇게 빨리 줄지?" 싶을 때가 있습니다.
대부분은 **컨텍스트 크기**와 **캐시** 두 가지로 설명됩니다. 이 문서는 그 규칙과 아끼는 습관을 정리합니다.

> 기준: Claude Code 공식 문서 [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching), [Manage costs effectively](https://code.claude.com/docs/en/costs), Claude API [가격](https://platform.claude.com/docs/en/about-claude/pricing) (2026-10 확인). 버전이 바뀌면 세부 내용이 달라질 수 있습니다.

## 1. 메시지 하나에 무엇이 실려 가나

Claude는 이전 대화를 기억하지 못합니다. 그래서 Claude Code는 **메시지를 보낼 때마다 대화 전체를 다시 보냅니다.**

- 시스템 프롬프트와 도구 정의
- CLAUDE.md, 메모리 같은 프로젝트 정보
- 지금까지의 모든 메시지, Claude의 답, **도구 결과**(읽은 파일, 명령 출력 등)
- 새 메시지

또 Claude가 도구를 한 번 쓸 때마다 그 결과를 붙여 요청을 다시 보냅니다. 한 턴에 도구를 10번 쓰면 대화 전체가 10번 오가는 셈입니다.

**정리하면, 대화가 길수록 짧은 질문 하나도 비싸집니다.** 하루 종일 연 세션에서 "고마워" 한 줄을 보내도 대화 전체만큼 사용량이 듭니다.

## 2. 캐시가 이 비용을 크게 줄여 준다

매번 전체를 보내지만, 앞부분이 직전 요청과 **똑같으면** 서버가 이미 처리해 둔 결과(캐시)를 다시 씁니다. 새로 붙은 부분만 제대로 처리합니다.

API 정가 기준으로, 일반 입력 토큰 가격을 1이라고 하면:

- **캐시 읽기**: 약 0.1 (90% 할인)
- **캐시 쓰기, 5분 캐시**: 약 1.25
- **캐시 쓰기, 1시간 캐시**: 약 2

구독(Pro, Max, Team, Enterprise)은 달러로 청구되지 않지만, 같은 원리로 **사용량 한도**를 덜 쓰거나 더 씁니다.

**핵심**: 캐시가 살아 있으면 긴 대화도 싸게 이어 갈 수 있습니다. 캐시가 깨지거나 만료되면 대화 전체를 비싼 값으로 다시 기록합니다.

## 3. 캐시는 얼마나 살아 있나

마지막 요청 뒤로 아무 요청이 없으면 캐시가 만료됩니다. 요청이 캐시를 읽을 때마다 타이머가 처음부터 다시 시작합니다.

- **구독 플랜, 한도 안에서 쓸 때**: 메인 대화는 **1시간**, subagent와 compact 같은 나머지 요청은 5분
- **한도를 넘어 추가 사용량(usage credits)으로 쓸 때**: 메인 대화도 5분으로 바뀜
- **API 키, Bedrock 같은 클라우드 제공자**: 5분 (설정 `promptCacheTtl`을 `"1h"`로 바꿀 수 있음)

그래서 **한 시간 넘게 자리를 비우면**, 돌아와 보내는 첫 메시지가 대화 전체를 다시 기록합니다. 대화가 클수록 이 한 번이 큽니다.

## 4. 캐시를 깨는 행동, 깨지 않는 행동

캐시는 "앞부분이 글자 하나까지 똑같을 때"만 맞습니다. 그래서 앞부분을 바꾸는 행동은 다음 요청 한 번을 비싸게 만듭니다.

**깨는 행동** (다음 요청이 대화 전체를 다시 처리)

- `/model`로 **모델 바꾸기**: 모델마다 캐시가 따로입니다.
- **effort 바꾸기**: 대부분의 모델에서 깨집니다. 단, Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1을 구독이나 API 키로 쓰면 유지됩니다.
- **fast mode 처음 켜기** (대화당 한 번)
- **MCP 서버 연결, 제거**: 도구 검색(기본값)이 켜져 있으면 대부분 유지됩니다.
- **`/compact`**: 대화를 요약본으로 바꾸므로 대화 부분이 새로 시작됩니다.
- **이미지를 아주 많이 붙였을 때**: 오래된 이미지가 빠지면서 다시 처리합니다.
- **Claude Code 업데이트 후 첫 대화**

**깨지 않는 행동**

- 저장소 파일 수정
- 대화 중 CLAUDE.md 수정 (대신 `/clear`, `/compact`, 재시작 전까지 반영되지 않음)
- 권한 모드, 출력 스타일 바꾸기
- 스킬, 슬래시 명령 실행
- `/rewind`로 이전 턴으로 되돌리기
- subagent 실행 (subagent는 자기 캐시를 따로 씀)
- 플러그인의 스킬, 명령, 훅, mod 켜고 끄기 (MCP 서버가 든 플러그인은 위의 MCP 규칙을 따름)

## 5. 한도와 자동 compact

- **5시간 한도**: 최근 5시간 동안 쓴 양. 5시간 창이 지나면 리셋됩니다.
- **주간 한도**: 7일 단위. 모든 모델이 같은 한도를 나눠 씁니다.
- **컨텍스트 창**: 한 대화가 담을 수 있는 최대 크기입니다. 기준선에 가까워지면 **자동 compact**가 앞부분을 요약해 공간을 만듭니다. 요약하면서 세부 내용이 사라질 수 있고, 요약 요청 자체도 대화 전체를 읽는 큰 요청입니다.

## 6. 바로 쓸 수 있는 절약 습관

1. **작업이 바뀌면 `/clear`**: 관계없는 이전 대화를 매 메시지마다 끌고 다니지 않습니다. `/clear`는 비용이 들지 않습니다. 나중에 찾으려면 먼저 `/rename`으로 이름을 붙이고, `/resume`으로 돌아옵니다.
2. **모델과 effort는 세션 시작 때 정하고 중간에 바꾸지 않기**: 바꿀 때마다 대화 전체를 다시 처리할 수 있습니다.
3. **`/compact`는 작업 사이 쉬는 지점에서**: 작업 도중 자동 compact가 끼어들지 않게 합니다. 남길 내용을 정해 줄 수 있습니다. 예: `/compact 테스트 결과와 코드 변경 위주로 남겨`
4. **잘못 간 길은 `/rewind`**: Esc로 멈추고 `/rewind`로 되돌리면 이미 캐시된 지점으로 돌아가므로 compact보다 쌉니다.
5. **한 시간 넘게 쉴 때**
   - 금방 돌아오면 그대로 둡니다. 다음 메시지가 캐시를 갱신합니다.
   - 오래 쉬고 그 대화를 이어 갈 거라면 캐시 유지(`/keepwarm`, token-gauge의 `유지 90분`)를 켜 둡니다.
   - 대화가 너무 크다면 인계 메모를 남기고 새 세션에서 시작하는 편이 쌀 수 있습니다.
6. **요청을 구체적으로**: "코드 개선해 줘"는 넓게 뒤지느라 파일을 많이 읽습니다. "auth.ts의 login 함수에 입력 검증 추가"처럼 범위를 좁혀 주세요.
7. **큰 출력은 대화 밖에서**: 긴 로그, 테스트 전체 출력, 문서 조사는 subagent에게 맡기면 요약만 돌아옵니다. 반복되면 훅으로 실패 줄만 남기게 할 수 있습니다.
8. **쓰지 않는 MCP 서버 끄기**: `/mcp`에서 끕니다. `gh` 같은 CLI 도구가 있으면 그쪽이 보통 더 가볍습니다.
9. **CLAUDE.md는 짧게**: 매 세션 매 메시지에 실립니다. 200줄 이하를 권장하고, 특정 작업에만 필요한 지침은 skill로 옮기면 필요할 때만 읽힙니다.
10. **가벼운 일은 가벼운 모델로**: 대부분의 코딩은 Sonnet으로 충분합니다. 단순한 일은 effort를 낮추세요(`/effort`).
11. **복잡한 일은 계획 모드부터**: `Shift+Tab`으로 계획 모드에서 방향을 먼저 맞추면 잘못 만든 걸 다시 만드는 낭비를 줄입니다.
12. **확인하기**: `/usage`로 플랜 사용량과 `Prompt cache (main)` 줄(적중률, 재기록 횟수, 지금 캐시 상태)을, `/context`로 무엇이 컨텍스트를 채우는지 봅니다.

## 7. token-gauge로 읽는 법

- **plan 칩이 노랑, 빨강**: 한도에 가까워졌습니다. 5h 막대의 채움이 회색 눈금보다 앞서 있으면 지금 속도가 빠른 것입니다.
- **context 칩이 ☂, ☇로 바뀜**: compact가 멀지 않았습니다. `≈ N턴`이 작아지면 작업 경계에서 `/compact`하거나 인계 메모를 남기세요.
- **`▲` 증가량이 갑자기 큼**: 상세의 "지난 턴"에서 어떤 도구 결과가 컸는지 보고, 다음엔 범위를 좁혀 읽게 하세요.
- **❄ 캐시가 노랑**: 10분 안에 식습니다. 곧 이어 쓸 거면 무시하고, 오래 쉴 거면 유지 버튼이나 `/compact`를 고려하세요.
- **❄ cold**: 다음 메시지가 대화 전체를 다시 기록합니다(`재기록 ~Nk`). 대화가 크다면 새 세션이 나을 수 있습니다.
